# 09 — AI Interaction Log | Mini Issue Tracker

**Проєкт:** Mini Issue Tracker  
**Призначення:** журнал нової документованої сесії доопрацювання практичної роботи після зауважень викладача  
**Версія:** 1.0 (етап 7)  
**Дата складання журналу:** 2026-11-11  
**Статус:** `DOCUMENTED FROM CURRENT CHAT / HUMAN VALIDATION PENDING`  
**Публічний діалог ChatGPT:** `PENDING — PUBLIC SHARE LINK`  
**Репозиторій:** https://github.com/yaroslavtantsur10/Mini_Issue_Tracker  
**Figma Design:** https://www.figma.com/design/B5nr6SR4YnQztz8cmqTPaa/Untitled?node-id=0-1

> **Межі достовірності.** Цей журнал описує **лише поточний діалог** про доопрацювання після зауважень викладача. Це не реконструкція первинної сесії створення практичної роботи, історії Figma Agent чи локальних дій студента. Тексти в лапках нижче — дослівні витяги з видимих запитів користувача; записи про артефакти ґрунтуються на відповідях AI та наявних локальних Markdown-файлах. Дата `2026-11-11` підтверджена датами редакцій отриманих артефактів і поточною датою розмови; **окремі точні дати/час кожного повідомлення не підтверджені метаданими чату**. Жодного схвалення викладача, реального тестового PASS або редагування Figma в цьому журналі не заявлено.

## 1. Джерела та правила фіксації

| Джерело | Використання | Обмеження |
|---|---|---|
| Поточний ChatGPT-діалог: запити й відповіді етапів 1–7 | Послідовність завдань, точні витяги з промптів, заявлені результати й обмеження | Не є журналом натискань у Figma, GitHub commits чи людських погоджень |
| `SD_Spec.docx` (завантажено як `SD_Spec(2).docx`) | Першоджерело Release MVP, BR і 33 AC | Джерело вимог, не свідчення реалізації |
| Методичні рекомендації Mini Issue Tracker (DOCX) | Контролі A–D; вимоги до traceability, контрактів, доказів та AI-журналу | Методика не підтверджує виконання студентом окремих дій |
| `02`, `03`, `04`, `05`, `07`, `08` та `Figma_Correction_Plan.md` у локальній сесії | Звірка підготовлених AI артефактів і версій | Наявність локального файлу не доводить його публікації в GitHub |
| GitHub `01_Input_Pack.md`, попередні документи та `evidence/*.png` (за звітами попередніх етапів) | Контекст порівняння й історичні візуальні свідчення | Цей журнал **не є повторною незалежною перевіркою** URL або зображень |

**Позначення:** `PREPARED` — AI створив файл; `SOURCE-RECONCILED` — заявлено звірку документів із S1; `REPORTED EVIDENCE` — наявність/результат відображено в попередньому протоколі; `NOT VERIFIED` — нема нової фактичної перевірки; `PROPOSED` — UX-рішення без затвердження людиною; `PENDING` — потрібна дія людини.

**Часова точність:** етапи нижче йшли в зафіксованій послідовності. Для кожного наведена **дата сесії / дата редакції артефактів: 2026-11-11**, а не вигаданий timestamp конкретного запиту.

  > «Побудуй повну AC-level Traceability Matrix для всіх 33 критеріїв.»
  >
  > «Якщо доступу до специфікації недостатньо, попроси завантажити її перед формуванням остаточного документа.»
  >
  > «Надаю повну вихідну специфікацію SD_Spec.docx. Продовжуй етап 1 — Requirements Traceability.»
  >
  > «Не позначай тести як PASS без доказів.»
- **Хід і відповідь AI:** спочатку повідомлено про недостатність першоджерела та запитано `SD_Spec.docx`; після його отримання підготовлено версію 2.0 матриці зі збереженням 33 AC, чотирьох ненумерованих пунктів US-03, джерел, screen/control/test/evidence/status та списком питань для погодження.
- **Підготовлений артефакт:** `03_Screen_Contracts_Traceability.md` **v2.0** (проміжна версія; на етапі 2 замінена v2.1).
- **Перевірка людиною:** користувач надав повну специфікацію й поставив вимоги до перевірки; **немає зафіксованого незалежного людського приймання 33 рядків або статусу APPROVED**.
- **Неперевірене / обмеження:** зв'язок тесту з вимогою не означає проходження; реальні Figma interactions, збереження в БД і погодження відсутні.
- **Подальша дія:** розгляд вихідних критеріїв людиною та перенесення узгодженого документа в GitHub.

## 3. Межі участі людини та AI

| Дія | Що підтверджує поточний діалог | Чого він **не** підтверджує |
|---|---|---|
| Постановка завдань і уточнень | Користувач сам сформулював запити, надав `SD_Spec.docx`, наголосив на збереженні source BR/AC і evidence boundaries | Формальне затвердження кожної AI-відповіді викладачем |
| Документальна підготовка | AI підготував зазначені Markdown-файли та заявив про джерельну звірку | Те, що кожен файл уже замінив стару версію в GitHub |
| Редагування Figma | AI підготував brief і correction plan; користувач повідомив про вже опубліковані візуальні стани | Що AI або студент у цій сесії фактично відредагували макет |
| Prototype Present | AI підготував test cases і manual checklist | Нові незалежно виконані `PASS`/`FAIL` для PT-01–PT-21 |
| Реальна реалізація | IT-01–IT-07 заплановані | Працююча БД, авторизація, HTTPS, backup, збереження або виміряна продуктивність |
| Decision Log | D-01–D-08 розглянуто; D-06 = `Select → Apply` як proposal | Статуси `APPROVED`, особи/дати погодження |
| Final Review | Висновок документа v2.0 — `NOT READY` | Фінальне приймання роботи викладачем |

## 4. Публічний ChatGPT-діалог

**Share URL:** `PENDING — PUBLIC SHARE LINK`

**Дії після отримання посилання:** користувач створює Share link саме для цієї розмови; перевіряє, що там видно доречні етапи й немає матеріалів, які не слід публікувати; замінює placeholder на **фактичний** URL; за потреби додає дату публікації за реальним свідченням. AI не генерував і не перевіряв URL та не заявляє, що розмова вже є публічною.
